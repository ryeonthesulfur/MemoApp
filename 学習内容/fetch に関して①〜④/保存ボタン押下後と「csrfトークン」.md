# 【JavaScript徹底解説】保存ボタンの裏側と「身分証明書(CSRFトークン)」の秘密    2026. 7/20 ①

このドキュUMENTでは、`memo_saving.js`ファイルにある以下の2行のコードが、一体何をしているのかを、誰でも理解できるように徹底的に解説します。

```javascript
save_btn.addEventListener('click', function () {
    const csrfToken = document.querySelector('meta[name="csrf-token"]').content;
    // ... この後、通信処理が続く
});
```

---

## 1. 「もしボタンが押されたら、これを実行せよ」と予約する (addEventListener)

まず1行目を見ていきましょう。

```javascript
save_btn.addEventListener('click', function () { ... });
```

これは、**イベントの予約**をしています。

### 比喩で理解しよう！

`addEventListener`は、まるで**優秀な秘書**に指示を出すようなものです。

*   `save_btn`: 「秘書さん、**保存ボタン**をよく見ておいてください」
*   `'click'`: 「もし、そのボタンが**クリックされたら**...」
*   `function () { ... }`: 「...その瞬間に、**この `{}` の中に書かれた仕事**をしてください」

つまり、このコードが読み込まれた瞬間には、`{}`の中身はまだ実行されません。
これはあくまで「ユーザーが保存ボタンをクリックした**未来の時点**で、この処理を実行する」という**予約**を登録しているだけなのです。

---

## 2. 「この通信は本物です」と証明する身分証明書 (CSRFトークン)

次に、予約された仕事の1行目、今回の最重要ポイントです。

```javascript
const csrfToken = document.querySelector('meta[name="csrf-token"]').content;
```

これは、通信の安全性を保つための**「身分証明書」**を取得している処理です。

### Part 0: そもそも「CSRFトークン」と「csrf_meta_tags」って何？

先に進む前に、この2つの言葉をはっきり分けておきます。似た名前ですが**別のものです**。

**CSRFトークンとは**

ただの**ランダムな文字の並び**です。例えば`aB3xY9Zp...`のような文字列で、それ以上でも以下でもありません。特別な仕組みがあるわけではなく、「Railsがページを表示するたびに新しく作って、後で照合に使う文字列」というだけのものです。

**`<%= csrf_meta_tags %>`とは**

これは`app/views/layouts/application.html.erb`に書かれている**Rubyのコード**です。`<%= ... %>`は「ここでRubyのコードを実行して、その結果をHTMLに埋め込む」という意味のERBの書き方です。

`csrf_meta_tags`はRailsが用意している関数(メソッド)の名前です。これが実行されると、上の「ランダムな文字列」を使って、こういうHTMLタグを1個作って出力します。

```html
<meta name="csrf-token" content="aB3xY9Zp...">
```

**関係を整理すると**

- `csrf_meta_tags`(Rubyの関数)を実行 → その結果として`<meta name="csrf-token" content="...">`というHTMLタグができる → そのタグが実際にブラウザに送られるHTMLの中に入っている
- JS側の`document.querySelector('meta[name="csrf-token"]').content`は、その**できあがったHTMLタグ**から、ランダムな文字列を取り出しているだけ

つまり「CSRFトークン」=文字列そのもの、「`csrf_meta_tags`」=そのタグを作るためのRubyのコード、という別物です。

### Part 1: なぜ「身分証明書」が必要なのか？ (CSRF対策)

**問題点：なりすまし通信の危険**

もし、悪意のある偽サイトに「あなたのメモを全部消す」という命令を裏で実行するボタンが仕込まれていたらどうでしょう？あなたが気づかずにそれをクリックすると、あなたの知らないうちにMemoAppに対して「メモを消せ」というリクエストが送られてしまいます。これを**CSRF（クロスサイト・リクエスト・フォージェリ）攻撃**と呼びます。

**解決策：身分証明書(CSRFトークン)の確認**

この攻撃を防ぐため、Railsは「本当にうちのサイトから送られた正規のリクエストか？」を確認する仕組みを持っています。

1.  Railsはページを表示するたびに、ユニークな**「身分証明書（CSRFトークン）」**を発行し、HTMLに埋め込みます。
2.  データを変更するリクエスト（保存、更新、削除など）を受け取ったとき、Railsは「その身分証明書を見せなさい」と要求します。
3.  偽サイトからのリクエストには正しい身分証明書が含まれていないため、Railsはそれを「不正なリクエスト」と判断してブロックします。

通常の`<form>`を使った送信ではRailsが自動でこの身分証明書を付けてくれますが、今回のようにJavaScriptの`fetch`で自力で通信を行う場合は、**自分で身分証明書を探して、リクエストに添付してあげる必要があります。**

### Part 2: 「身分証明書」はどこにある？どうやって見つける？

この一行は、その「身分証明書」を探し出すための命令です。

`const csrfToken = document.querySelector('meta[name="csrf-token"]').content;`

1.  **`document.querySelector('meta[name="csrf-token"]')`**
    *   これはブラウザへの命令です。「このHTMLページ全体から、`<meta>`というタグで、かつ`name="csrf-token"`という属性を持つものを**1つ見つけてきてください**」
    *   このタグは、`app/views/layouts/application.html.erb`にある`<%= csrf_meta_tags %>`によって、ページが読み込まれるたびに自動で生成されています。HTMLの中では以下のように見えます。
        ```html
        <meta name="csrf-token" content="長いランダムな文字列...">
        ```

2.  **`.content`**
    *   「先ほど見つけてきた`<meta>`タグの、`content`属性の**中身（値）**を取り出してください」
    *   これにより、`"長いランダムな文字列..."`という、身分証明書の本体が取得できます。

3.  **`const csrfToken = ...`**
    *   「取り出した身分証明書の文字列を、`csrfToken`という名前の**変数（箱）**に入れて保管しておいてください」

### Part 3: 「身分証明書」を提示する

こうして取得した`csrfToken`変数は、この後の`fetch`処理で、以下のようにリクエストのヘッダー（通信の付加情報）に含められます。

```javascript
headers: {
  'X-CSRF-Token': csrfToken, // ← ここで身分証明書を提示！
},
```

**この1行の意味を、もう少し分解します。**

HTTPリクエストには「本文(body)」と「ヘッダー」という2つの部分があります。

- **本文(body)**: 実際に送りたいデータ。今回で言えば`JSON.stringify({ memo: {...} })`の部分、つまり保存したいメモの中身
- **ヘッダー**: 本文とは別に付ける「付加情報」。「このリクエストについての説明書き」のようなもの

`headers: { 'X-CSRF-Token': csrfToken }`は、この**ヘッダー(付加情報)**の中に、

1. `'X-CSRF-Token'`という**名前**で
2. `csrfToken`という**値**(前の行で取り出したあの文字列)を

1つ追加する、という意味です。JSのオブジェクトの書き方(`{ キー: 値 }`)そのままです。

**なぜここに付けるのか**

Railsは「保存して」というリクエストを受け取った時、本文の中身(メモのタイトルとか)ではなく、**このヘッダーの`X-CSRF-Token`という項目**を見て、「正しいトークンが付いてるか」をチェックします。ここに正しい値が入ってないと、Railsはリクエストそのものを拒否します。

つまりこの1行は、「本文とは別に、`X-CSRF-Token`という名前で、さっき取り出したトークンの値を、リクエストに添付する」という指示です。

これにより、Railsサーバーは「おお、正しい身分証明書を持っているな。正規のユーザーからのリクエストに違いない」と判断し、安心してメモの保存処理を実行してくれるのです。

## まとめ

*   `addEventListener`: ユーザーの操作（クリックなど）をきっかけに、特定の処理を実行させるための**予約機能**。
*   `querySelector`でCSRFトークン取得: なりすまし通信を防ぐための**「身分証明書」**をHTMLから探し出し、JavaScriptで使えるように変数に保管する処理。

この2つは、RailsアプリでリッチなUIをJavaScriptで作る際の、基本かつ非常に重要なテクニックです。
