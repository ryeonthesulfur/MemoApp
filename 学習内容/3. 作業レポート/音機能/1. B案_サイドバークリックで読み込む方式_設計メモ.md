## 2. B案とは

**ページを移動せず、サイドバーをクリックした時に、JSでサーバーから画面の中身(パーシャルのHTML)を取得して、右側の入れ物に差し込む方式。**

サイドバーから選ばれるまで、パーシャルは一切描画しない。

### 流れ

1. **トップ画面を開いた時**: サイドバーと、右下の「MIND PALACE」だけが表示されている。`index.html.erb`の`render`2行は外して、代わりに空の入れ物(例: `<div id="main_area"></div>`)を置く
2. **サイドバーの「音」をクリック**: JSが`fetch("/sound")`で、「音」のパーシャルのHTMLをサーバーから取得
3. **取得したHTMLを差し込む**: `main_area.innerHTML = html`。入れ物の前の中身は、この時に自動で消える
4. **同時に**`main_title`(MIND PALACE)に`hide`クラスを付けて、消す

---

## 3. サーバー側で必要なもの

- ルーティング: `get "sound"`・`get "memory"`など
- コントローラー: 各アクションで、パーシャルだけを返す(`render partial: "top/sound"`など、レイアウトは付けない)
- 「憶」用のアクションでは、今`top#index`でセットしている`@folders`・`@memos`もセットする(`_memory`パーシャルがこの2つを使っているため)

## 4. JS側の変更(一番手間がかかる部分)

### 4-1. なぜ変更が要るのか

今の`top.js`・`folder_saving.js`・`memo_saving.js`・`select.js`・`show_panel.js`・`folder_columns.js`は、ページを開いた時(`turbo:load`)に、`add_btn`・`memo_panel`・`icon_container`などの要素を取得して、クリックの設定をしている。

B案では、これらの要素は「憶」のパーシャルを**差し込んだ後**にしか画面に存在しない。ページを開いた時点では、取得しようとしても見つからない。

### 4-2. どう変えるのか

「憶」のパーシャルの中にある要素に設定しているものを、各ファイルから関数として取り出し(`export`)、まとめて呼べる形にする。呼ぶタイミングは、**サイドバーをクリックした瞬間ではなく、パーシャルを差し込んだ直後**。

```
サイドバーの「憶」をクリック
  → fetch("/memory")で、パーシャルのHTMLを取得
  → main_area.innerHTML = html      ← 先に差し込む(ここで初めて add_btn などが画面に存在する)
  → 束ねた関数を呼ぶ                ← 差し込んだ後でないと、要素が無くて失敗する
```

| 種類 | 対象 | どうするか |
|---|---|---|
| 束ねる | 「憶」のパーシャルの**中にある要素**への設定(`add_btn`・`memo_panel`・`icon_container`・`folder_columns_container`・詳細パネルなど) | 関数にまとめて、差し込むたびに呼ぶ |
| 束ねない | サイドバーの「憶」「音」のクリック自体(レイアウトにある要素) | これまで通り、ページを開いた時に1回だけ設定する |

### 4-3. 二重登録に注意

`document`に付けている設定(`select.js`の⑤など)は、差し込むたびに呼ぶと、同じ設定が何個も重なって登録されてしまう。「1回だけ登録する部分」と「差し込むたびにやる部分」を分ける必要がある。

### 4-4. 「写真を撮り直す」問題と同じ

`window.icon_container`のように、`window`に載せている要素は、差し込みで要素が入れ替わると、古い(もう画面に無い)要素を指したままになる。差し込むたびに、`window`に載せ直す必要がある(`JSファイル間での変数.md`の「Turbo環境でDOM要素を扱う際の注意点」と同じ話)。

## 5. 音楽について

ページ移動が起きないので、Webampを`main_area`の**外**(レイアウト側)に置けば、「憶」や「時」に切り替えても止まらない。`data-turbo-permanent`も要らない。

止まるのは、ブラウザの更新(F5)をした時だけ。

---

## 6. 「憶」で開いていたものを閉じる件

「音」に切り替える時に`main_area`の中身を入れ替えるので、「憶」のパネルやカラムは自動的に消える。閉じる処理を別に書く必要はない。
