# 作業レポート：ビジュアライザーを共通の背景にする  261107

別タブで開いていたアンビエント用のビジュアライザーを、アプリ全体の背景にした。「憶」「時」「音」とページを移っても止まらずに動き続ける。元の背景画像とは、サイドバーのボタンで切り替えられる。PR #39 でマージ済み。

<br>

---

## 1. 方針を決めた話し合い

### 1-1. やりたいこと

- ビジュアライザーを共通レイアウトに入れて、どの画面でも背景として動かし続ける。
- 元の背景画像は残して、切り替えられるようにする。
- Webamp は今のまま。背景のビジュアライザーは、音には反応させず、静かに動かすだけにする。

最初、私は「Webamp の曲に反応させる」話まで広げてしまったが、それは読み違いだった。

<br>

### 1-2. 音楽はもともと止まらない作りだった

- Webamp の入れ物は、ページを移っても取り替えない設定（data-turbo-permanent）で、共通レイアウトに置いてあった。
- そのため、「憶」「時」に移っても、曲は鳴り続けていた。他のページでは、CSS で見た目を隠しているだけだった。
- ビジュアライザーも、同じ方法で置けば止まらない、という結論になった。

<br>

### 1-3. GPU は「減る」のか

| 疑問 | 答え |
|---|---|
| GPU は使うと減る（傷む）？ | 普通の使い方では、まず傷まない |
| では何が増える？ | 電気代・熱・ファンの音・ノートPCの電池の減り。動画を流しっぱなしにしているのに近い |
| クオリティを落とさずに減らせる？ | 見えていない時に止めれば、見た目を変えずに減らせる |

- そこで、背景画像に切り替えている間は、ビジュアライザーを描くのを止めることにした。
- ブラウザを最小化した時や、別のタブを見ている時は、ブラウザが自動で止めてくれる。
- 実際に重いかどうかは、Mac の「アクティビティモニタ」で測ってから考える（まだ測っていない）。

<br>

## 2. ビジュアライザーを、アプリの中で使える形に移す

### 2-1. three.js をアプリの中に取り込んだ

- 別タブ版は、毎回ネットの向こう（jsdelivr）から three.js を読んでいた。
- 背景は毎回出るものなので、Webamp と同じように、手元（vendor/javascript）に置いた。ネットの向こうの都合で、背景が出なくなることがないようにするため。
- 金属の映り込みに使う追加の部品（RoomEnvironment）も、同じ場所に置いた。
- three.js は約700KBある。そこで、**ビジュアライザーを背景に選んだ時だけ読み込む**設定にした（importmap の `preload: false`）。背景画像を選んでいる人にまで、読ませないため。

<br>

### 2-2. 背景用のビジュアライザーを作った

`app/javascript/ambient_background.js`

- 中身は、別タブ版と同じ空間（塔のブロック、中心の光、遠くから来る塵）。
- 背景では音に反応させないので、次のものを外した。
  - 音を読み取る部分
  - つまみなどの操作パネル
- その結果、見た目は、別タブ版で**音が鳴っていない時**と同じになる。デモ音を流していた時より、中心の光や塵が少し控えめになる。
- **止める・再開する仕組み**を足した。
  - 再開した時に、塔などが急に飛ばないようにした。止めていた間の時間を、動きの計算に数えないためである。

<br>

## 3. 共通レイアウトの背景にする

### 3-1. 描く場所を、画面のいちばん後ろに置いた

- 共通レイアウト（application.html.erb）に、描く場所（canvas）を置いた。
- Webamp の入れ物と同じく、ページを移っても取り替えない設定にした。描き直しにならず、そのまま続く。
- 最初のページを開いた時に1回だけ描き始めて、3秒かけて暗闇からふわっと出す。

<br>

### 3-2. 背景画像を、CSS の側から付けるように変えた

- 今までは、背景画像を HTML の中に直接書いていた。
- HTML に直接書かれていると、CSS から外せない。そこで、画像の場所だけを HTML から渡して、画像を付けるのは CSS で行うようにした。
- 画像の場所（ファイル名に付く番号）は Rails でないと決められないので、HTML から渡す形にしている。

<br>

### 3-3. 上にかける暗い膜

- 背景画像の時の膜は、下の方で75%の黒。
- このままビジュアライザーに使うと、塔がほとんど見えなくなる。そのため、ビジュアライザー用には、もっと薄い膜（15%〜45%）を別に用意した。

<br>

## 4. 背景の切り替えボタン

### 4-1. 見た目と動き

- サイドバーの電源ボタンのすぐ上に、壁紙のアイコンを置いた。
- 押すたびに、「ビジュアライザー」と「背景画像」が、2秒かけてふわっと入れ替わる。

<br>

### 4-2. ふわっと入れ替える仕組み

- 背景画像そのものは、CSS ではふわっと切り替えられない。
- そこで、次の3つを別々の層にして重ねた。
  1. ビジュアライザー（いちばん後ろ）
  2. 背景画像（上に暗い膜を重ねたもの）
  3. ビジュアライザー用の暗い膜
- 2 と 3 の透明度を入れ替えることで、ふわっと切り替わって見える。

<br>

### 4-3. 選んだ方を覚えておく

- 選んだ方をブラウザ（localStorage）に覚えさせる。ページを移っても、開き直しても、選んだ方のまま。
- 何も選んでいない時は、ビジュアライザーにしている。
- ブラウザの設定で覚えさせる場所が使えない時も、エラーにせず、ビジュアライザーにする。

<br>

### 4-4. 無駄に動かさない工夫

| 場面 | どうなるか |
|---|---|
| 背景画像に切り替えた時 | 背景画像が戻りきってから（2秒後）、ビジュアライザーを止める |
| 最初から背景画像を選んでいる時 | three.js を読み込まない |
| ビジュアライザーに戻した時 | 止めていたところから再開する |
| 読み込みの途中で、背景画像に戻された時 | 読み込みが終わっても、描き始めずに止めておく |

<br>

### 4-5. 開いた瞬間のチラつきを防ぐ

- どちらを出すかを JS で決めるのが画面を描いた後だと、選んでいない方が一瞬見えてから切り替わってしまう。
- そこで、レイアウトの `<head>` に短い判定を入れて、画面を描く前に決めておくようにした。

<br>

## 5. 確認したこと

- トップ → 「憶」→「音」と移っても、描く場所が作り直されず、同じものが動き続けていること。
- 「憶」「音」で、両方向に切り替えられること。
- 背景画像を選んだ後、ページを開き直しても背景画像のままで、three.js も読み込まれていないこと。
- コンソールにエラーが無いこと。

**気づいたこと**
- ブラウザのタブが裏に回っている時は、ふわっと切り替わるアニメーションが止まって見える。
- これはブラウザの仕組みで、アプリの不具合ではない。タブを前に出したら、正しく切り替わった。
