## 1. やりたいこと

- サイドバーの「憶」「時」「音」をクリックすると、右側にその画面が出る
- 「音」の画面にはWebampを置く。**音楽を流している間に「憶」や「時」の画面に切り替えても、音楽を止めたくない**
- 「憶」で作業している途中で「音」をクリックしたら、「憶」で開いていたパネルなどは全部閉じたい
- トップ画面を開いた時は、サイドバーから選ばれるまで、右下に「MIND PALACE」だけを表示しておく

## 2. C案とは

**サイドバーの各項目を、それぞれ別のURLへの`href`付きリンクにする方式。** クリックするとそのURLのページに移り、右側にその画面が出る。

コエテコカレッジのサイドバーが、開発者ツールで確認したところ、この形(`href`で1つ1つURLが振ってある)になっていた。

### URLの割り当て(案)

| URL | 表示するもの |
|---|---|
| `/` | サイドバーと、右下の「MIND PALACE」だけ(トップ画面) |
| `/memory` | 「憶」の画面(`_memory`パーシャル) |
| `/sound` | 「音」の画面(`_sound`パーシャル、Webampを置く) |
| `/time`(今後) | 「時」の画面 |

### 仕組み

レイアウト(`application.html.erb`)に、サイドバーと`<%= yield %>`(右側の表示場所)がある。各URLのビューが`yield`の部分に入る。リンクをクリックすると、Turbo Driveが**ページを再読み込みせずに**`<body>`の中身だけを入れ替えるので、体感は「右側が切り替わる」になる。

---

## 3. サーバー側で必要なもの

- ルーティング: `get "memory"`・`get "sound"`など
- コントローラー: 各URLのアクションと、対応するビュー(`memory/index.html.erb`など。中で該当のパーシャルを`render`する)
- 「憶」のアクションでは、今`top#index`でセットしている`@folders`・`@memos`もセットする(`_memory`パーシャルがこの2つを使っているため)
- `top#index`(`/`)は、`render`2行を外して、MIND PALACEだけの画面にする

B案と比べて、サーバー側の作業量はほぼ同じ。

## 4. JS側の変更

### 4-1. 今のJSは、ほぼそのまま動く

「憶」のページ(`/memory`)を開くたびに、`turbo:load`が発火して、今の6ファイル(`top.js`・`folder_saving.js`・`memo_saving.js`・`select.js`・`show_panel.js`・`folder_columns.js`)の設定が走る。「憶」の要素はそのページに最初から存在しているので、今のJSは大きく作り直さなくてよい。

この点が、JSの大幅な作り直しが要るB案との一番の違い。

### 4-2. 足す必要があるもの

**① 「要素が無ければ何もしない」の1行(各ファイル)**
「音」のページには、「憶」の要素(`add_btn`・`memo_panel`など)が存在しない。`getRefs()`は見つからない要素を`null`で返し、各ファイルはその`null`に`addEventListener`しようとして、エラーになる。各ファイルの先頭に「必要な要素が無ければ、そこで`return`する」を入れる。

**② `document`に付けている設定の二重登録対策**
`select.js`の⑤のように、`turbo:load`の中で`document`に設定している処理は、ページを移って戻るたびに、同じ設定が追加されて二重になる(チェックボックスを2回反転して、変わらないように見える)。1回だけ登録する形に直す必要がある。(B案でも同じ問題がある)

**③ 「憶」のクリックの挙動(今はJSでパネルを開閉)の見直し**
今の`top.js`の④は、「憶」をクリックするとパネルを開閉する処理。C案では、サイドバーの「憶」は`/memory`へのリンクになる。パネルは、`/memory`を開いた時点で表示済みにするか、開いた後にJSで`show`を付けて演出するかを決める必要がある。

**④ BGMの再生開始処理(`top.js`の②)の置き場所**
今は`top.js`の中で、`<audio id="bgm">`が存在する前提で動いている。C案では、全ページに存在するレイアウト側に`<audio>`(またはWebamp)を置くので、この処理も全ページで動く場所に移す。

### 4-3. レイアウトに置いてある要素の切り替えは、ページごとにサーバーで決める

`header_title`(ヘッダーの「記憶」)と`main_title`(MIND PALACE)は、レイアウトにある。今はJSで`show`/`hide`クラスを付け外ししているが、C案では、ページごとに何を表示するかが決まっているので、サーバー側(ビューやレイアウトの条件分岐)で決められる。

- 見出し3つ(記憶・カレンダー・音)が全部`id="header_title"`になっている問題も、各ページが自分の見出し1つだけを出す形にすれば、解消できる
- 「憶」で開いていたものは、ページ移動で`<body>`が入れ替わるので、自動的に消える(閉じる処理を別に書く必要がない)

## 5. 音楽を止めない方法

### 前提

このアプリはTurbo Driveを使っているので、リンクでページを移っても、ブラウザは**ページを再読み込みしない**(`<body>`の中身を入れ替えるだけ)。なので、JSの状態(`window`に載っているもの、JSで作ったオブジェクト)は、ページを移っても生き続ける。失われるのは、`<body>`の中にあって、`data-turbo-permanent`が付いていない**画面の要素**だけ。

### 方法1: Webampの入れ物を、レイアウトに置いて`data-turbo-permanent`を付ける

`id`と`data-turbo-permanent`を付けた要素は、Turboがページを入れ替える時に、入れ替えずに新しいページへ持ち越す。Webampの入れ物がこの中にあれば、画面も状態も残る。

### 方法2: 音を鳴らす部分を、画面(DOM)の要素に頼らない

今のBGMは、`index.html.erb`の`<audio id="bgm">`という、画面上の要素で鳴らしている。これを`window.bgm = new Audio("/bgm.wav")`のように、**JSだけで作ったオブジェクト**にして`window`に持たせれば、`<body>`が入れ替わっても、音は影響を受けない。

私の理解では、Webamp自体も内部では、音を鳴らす`<audio>`をJSで作っていて、画面には置いていない。その場合、音の再生そのものは、ページを移っても止まらない。残る問題は、Webampの見た目(画面)が、ページを移った時に消えないか、だけで、これは方法1で対処できる。

### 方法1と2の組み合わせ(有力)

- 音の再生: JSのオブジェクトとして`window`に持たせる(方法2)
- Webampの見た目: レイアウトに置いて`data-turbo-permanent`を付ける(方法1)。「音」のページ以外では、CSSで隠しておくこともできる

### それでも止まる場合

- ブラウザの更新(F5)
- `data-turbo="false"`のリンク、別タブで開くリンク
- CSS・JSが更新された後の移動(レイアウトの`data-turbo-track="reload"`により、全体が再読み込みされる)

## 7. B案との比較

| | B案(クリックで読み込む) | C案(別URLのリンク) |
|---|---|---|
| ページ移動 | しない | する(Turbo Driveなので再読み込みはしない) |
| 音楽が止まらないか | 確実に止まらない(ブラウザの更新を除く) | **実験で確認するまで確実とは言えない** |
| 「憶」を閉じる処理 | 入れ替えで自動的に消える | ページ移動で自動的に消える |
| 今のJSへの影響 | **大きい**(6ファイルの`turbo:load`の中身を、関数に取り出して作り直す) | **小さい**(各ファイルに1行足す、二重登録対策) |
| サーバー側の作業量 | ほぼ同じ | ほぼ同じ |
| コエテコカレッジと同じ形か | いいえ | はい(`href`でURLを分ける) |

**判断の基準**: 6章の実験で「止まらない」と確認できれば、作業が軽いC案。止まるなら、作業は多いが確実なB案。

## 8. 実装前に先に直す点(見つかっているもの)

1. `window.js`の`sound: document.querySelector('.item-boxes')[2]`は、`querySelector`が1個しか返さないので`undefined`になる。`memo`と同じ`querySelectorAll('.item-boxes')[2]`にする(C案ではサイドバーが`link_to`になるので、この`sound`自体が要らなくなる可能性がある)
2. `application.html.erb`の見出し3つ(記憶・カレンダー・音)が、全部同じ`id="header_title"`(4-3で整理できる)
3. 今の`sound.js`は、`top.js`からコピーしただけの断片で、`sound`・`panel`などが未定義。C案では、この「音」用のクリック処理自体が不要になる(リンクで移動するため)
4. (対応済み)`main_title`の`show`クラスが「消す」という逆の意味だったので、`hide`に名前を変えた(`4. エラー/main_titleのshowクラスが逆の意味だった問題_修正レポート.md`)
