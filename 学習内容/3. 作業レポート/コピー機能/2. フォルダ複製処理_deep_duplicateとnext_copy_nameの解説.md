# フォルダ複製処理、`deep_duplicate`と`next_copy_name`の解説  260913

`Folder`モデルに追加した、フォルダを複製する処理のうち、入口の`deep_duplicate`と、名前の採番を行う`next_copy_name`についてのまとめ。

---

## 0. お題にするコード

```ruby
def deep_duplicate
  ActiveRecord::Base.transaction do
    duplicate_into(parent_id)
  end
end

# 同じparent_idを持つ兄弟の中で、ベース名の"_copy(N)"のうち最大のNを探し、その+1を使った名前を返す
def self.next_copy_name(base_name, parent_id)
  base = base_name.to_s.sub(/_copy\(\d+\)\z/, "")
  max_n = where(parent_id: parent_id)
            .where("name LIKE ?", "#{base}_copy(%")
            .filter_map { |f| f.name[/_copy\((\d+)\)\z/, 1]&.to_i }
            .max || 0
  "#{base}_copy(#{max_n + 1})"
end
```

---

## 1. `deep_duplicate`: 入口の関数

```ruby
def deep_duplicate
  ActiveRecord::Base.transaction do
    duplicate_into(parent_id)
  end
end
```

複製したい大元のフォルダ(例: 「写真」フォルダ)に対して呼び出す、入口の関数。

- `ActiveRecord::Base.transaction do ... end`: この中の処理を「全部成功するか、1個も残らないか」のどちらかにする。フォルダ・メモを再帰的に作っていく途中でエラーが起きても、中途半端な複製が残らないようにするため([Railsのdupとid・saveのタイミング_解説.md](./Railsのdupとid・saveのタイミング_解説.md)、複製処理の失敗時の扱いに関する検討も参照)。
- `duplicate_into(parent_id)`: 実際の複製処理(別で定義してる、再帰する側のメソッド)を呼び出す。`parent_id`は「今の自分(元のフォルダ)の親」。つまり「複製先も、元のフォルダと同じ場所(同じ親フォルダの下)に置く」という意味。

`deep_duplicate`自体はほぼ何もしていない。「トランザクションで囲んで、実際の処理(`duplicate_into`)を呼ぶ」という、入口の役割に徹している。

---

## 2. `next_copy_name`: 新しい名前を決める関数

「新しく付けるべき名前」を決めて返すだけの関数。具体例で追う。

**例**: `next_copy_name("旅行", 5)`を呼んだとする(`parent_id`が5のフォルダの中に、「旅行」という名前のコピーを作りたい)。

### 1行目: 既存の`_copy(N)`を剥がす

```ruby
base = base_name.to_s.sub(/_copy\(\d+\)\z/, "")
```

正規表現`/_copy\(\d+\)\z/`は「文字列の**末尾**(`\z`)にある`_copy(数字)`」を探し、それを空文字に置き換える(=削除する)。

ここで剥がしてる対象は、「複製した直後に自動で割り振られた名前」ではなく、**複製元(まだ複製されていない、今ある方)の名前**。具体的には2パターンある。

- **ケースA**: 「旅行」というフォルダを、初めてコピーする → `base_name`には`"旅行"`が渡ってくる。`_copy(数字)`は付いてないので、正規表現は何もマッチせず、`base`もそのまま`"旅行"`
- **ケースB**: 「旅行_copy(1)」という、**既に1回コピーされたフォルダを、さらにもう一度コピーする** → `base_name`には`"旅行_copy(1)"`が渡ってくる。今度は正規表現がマッチして`_copy(1)`部分が削除され、`base`は`"旅行"`になる

つまりこの1行は「今からコピーしようとしてる相手の名前が、たまたま既にコピー品(`_copy(N)`付き)だったとしても、綺麗な元の名前まで剥がす」ための処理。

### 2〜5行目: 兄弟の中から最大の番号を探す

```ruby
max_n = where(parent_id: parent_id)
          .where("name LIKE ?", "#{base}_copy(%")
          .filter_map { |f| f.name[/_copy\((\d+)\)\z/, 1]&.to_i }
          .max || 0
```

| 行 | やってること |
|---|---|
| `where(parent_id: parent_id)` | 同じ親フォルダ(例: id=5)を持つ、兄弟フォルダだけに絞り込む |
| `.where("name LIKE ?", "#{base}_copy(%")` | その中で、名前が`"旅行_copy("`から始まるものだけに、さらに絞り込む(`%`はSQLの「何でもいい」というワイルドカード) |
| `.filter_map { \|f\| f.name[...] &.to_i }` | 絞り込んだ各フォルダの名前から、`_copy(数字)`の「数字」部分だけを取り出して数値に変換する。`filter_map`は「取り出した結果が`nil`のものは自動的に除外する」という、`map`の親戚 |
| `.max` | その数値のリストの中で一番大きいものを取る |
| `\|\| 0` | 該当するフォルダが1個も無ければ(`max`が`nil`になるので)、代わりに`0`を使う |

例えば「旅行_copy(1)」と「旅行_copy(2)」が既にあれば、`max_n`は`2`になる。まだ何も無ければ`max_n`は`0`になる。

### 最終行: 新しい名前を組み立てる

```ruby
"#{base}_copy(#{max_n + 1})"
```

`max_n`に1を足した番号を使う。既存が無ければ`"旅行_copy(1)"`、`_copy(2)`まであれば`"旅行_copy(3)"`になる。

---

## 3. 全体の処理順序

`next_copy_name`は単体では呼ばれず、`duplicate_into`(再帰する側のメソッド)の中で、以下の順番で使われている。

1. `dup`で複製する(まだ名前は元と同じ。この時点ではDBに保存されていない)
2. `next_copy_name`が呼ばれる。渡されるのは**複製元(自分自身)の`name`属性**
3. その名前から、既存の`_copy(N)`があれば剥がして`base`にする
4. 同じ`parent_id`を持つ兄弟を探し、`base_copy(`で始まる名前の中の最大値を探す
5. その最大値+1を使って、新しい名前を組み立てる
6. その名前を、複製した`new_folder`(手順1で作った方)の`name`に上書きする

「複製する → 名前を決める(剥がす → 兄弟を探す → +1する) → 複製した方にその名前を設定する」という順序。
