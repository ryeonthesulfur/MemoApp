# フォルダ複製処理、`target_parent_id`を1本の具体例で追う  260914

`duplicate_into`は自分自身を再帰的に呼び出す関数なので、「`target_parent_id`は結局どのフォルダのidなのか」が、**どの呼び出しの話をしてるか**によって変わる。ここを行き来して説明したため混乱を招いたので、1本の具体的な例で、id番号まで含めて最初から最後まで追う。

---

## 0. お題にするコード

```ruby
def deep_duplicate
  ActiveRecord::Base.transaction do
    duplicate_into(parent_id)
  end
end

def duplicate_into(target_parent_id)
  new_folder = dup
  new_folder.parent_id = target_parent_id
  new_folder.name = self.class.next_copy_name(name, target_parent_id)
  new_folder.save!

  memos.each do |memo|
    new_memo = memo.dup
    new_memo.folder_id = new_folder.id
    new_memo.title = Memo.next_copy_name(memo.title, new_folder.id)
    new_memo.save!
  end

  children.each { |child| child.duplicate_into(new_folder.id) }

  new_folder
end
```

---

## 1. 前提: 複製したいデータ

```
写真 (id=10, parent_id=nil)   ← ルート直下にあるフォルダ
 ├─ メモA
 ├─ メモB
 └─ 旅行 (id=11, parent_id=10)  ← 「写真」の子フォルダ
      └─ メモC
```

`写真.deep_duplicate`を呼んだとする。

---

## 2. 呼び出し①: `写真`自身の複製

`deep_duplicate`から、`duplicate_into(parent_id)`が呼ばれる。ここでの`parent_id`は**「写真」自身の`parent_id`**、つまり`nil`(写真はルート直下なので、親がいない)。

```ruby
duplicate_into(nil)   # target_parent_id には nil が入る
```

**この呼び出しの中で`self`は「写真」。**

| 行 | 内容 |
|---|---|
| `new_folder = dup` | 「写真」の中身をコピー(まだ`id`は`nil`) |
| `new_folder.parent_id = target_parent_id` | `nil`を設定(=ルート直下に置く) |
| `new_folder.name = next_copy_name("写真", nil)` | `parent_id=nil`(ルート直下)の兄弟の中で`"写真_copy("`を探す → 無ければ`"写真_copy(1)"` |
| `new_folder.save!` | 保存。**ここで新しいidが決まる。仮に`id=100`とする。** |

→ **この時点で、DBに「写真_copy(1)」(id=100, parent_id=nil)が保存された。**

続けて、メモA・メモBを、`folder_id=100`の下に複製する(処理は同じパターンなので省略)。

最後に子フォルダを処理する行。

```ruby
children.each { |child| child.duplicate_into(new_folder.id) }
# new_folder.id はこの時点で 100 (さっきsave!で決まった値)
```

「写真」の子フォルダは「旅行」だけなので、**`旅行.duplicate_into(100)`が呼ばれる。**

**この`children.each`の行こそが、「旅行」の複製を自動的に引き起こしてる部分。**

`children`は、今処理してる自分(ここでは「写真」)の子フォルダ一覧(`has_many :children`)。`.each`でそれを1個ずつ取り出し、`child.duplicate_into(new_folder.id)`を呼んでいる。「旅行」はこの`children`の中に入っているので、`写真.deep_duplicate`を呼んだだけで、この行が自動的に「旅行」に対しても`duplicate_into`を実行してくれる。呼び出す側(人間)が「旅行も複製して」と別途指示する必要はない。

もし「旅行」の中にさらに子フォルダがあれば、「旅行」自身の`duplicate_into`が実行された時(=呼び出し②の中)に、まったく同じこの行がまた実行され、さらに深い階層まで自動で潜っていく。

---

## 3. 呼び出し②: `旅行`自身の複製

ここが、呼び出し①とは**別の呼び出し**。`self`が「写真」から「旅行」に変わる。

```ruby
duplicate_into(100)   # target_parent_id には 100(写真_copy(1)のid)が入る
```

| 行 | 内容 |
|---|---|
| `new_folder = dup` | 「旅行」の中身をコピー(まだ`id`は`nil`) |
| `new_folder.parent_id = target_parent_id` | `100`を設定(=「写真_copy(1)」の中に置く) |
| `new_folder.name = next_copy_name("旅行", 100)` | `parent_id=100`(写真_copy(1)の中)の兄弟の中で`"旅行_copy("`を探す → 写真_copy(1)は今作られたばかりで中身が無いので、無い → `"旅行_copy(1)"` |
| `new_folder.save!` | 保存。**ここで新しいidが決まる。仮に`id=101`とする。** |

→ **この時点で、DBに「旅行_copy(1)」(id=101, parent_id=100)が保存された。**

続けてメモCを`folder_id=101`の下に複製し、「旅行」には子フォルダが無いので、再帰はここで終わる。

---

## 4. 1つの変数`target_parent_id`が指すもの、呼び出しごとの一覧

| 呼び出し | `self`(今処理してる自分) | `target_parent_id`の中身 | それが指してるもの |
|---|---|---|---|
| ① | 写真 (id=10) | `nil` | 「写真」自身の親(=ルートなので無し) |
| ② | 旅行 (id=11) | `100` | 「写真_copy(1)」のid(=①で複製・保存されたばかりのもの) |

**同じ「`target_parent_id`」という名前の引数でも、①と②では中身がまったく別の値。** これは、`duplicate_into`が再帰するたびに、新しい引数(その時点の`self`にとっての「複製先の親」)を渡し直しているため。「写真から見た旅行=子」「旅行から見たメモC=子」という relativity(相対的な関係)が、そのまま「呼び出しごとに変わる`target_parent_id`」として表れている。

---

## 5. `next_copy_name`が「探しに行くもの」の誤解について

呼び出し②の`next_copy_name("旅行", 100)`について、「idに該当する親フォルダを探し出して名前を付ける」という理解は誤り。

実際にやってることは、`where(parent_id: 100)`で**「parent_idが100であるフォルダたち(=写真_copy(1)の、今存在してる子フォルダたち)」を検索**し、その中に同じベース名の`_copy(N)`が無いか調べているだけ。「写真_copy(1)」という親フォルダのレコード自体(名前や中身)を取得する処理はどこにも無い。`100`という数字は、あくまで検索条件(絞り込みの軸)として使われているだけ。

---

## 6. 最後の1行`new_folder`の意味(返り値)

`duplicate_into`の一番最後は、こう終わっている。

```ruby
children.each { |child| child.duplicate_into(new_folder.id) }

new_folder
```

**Rubyのルール**: メソッドは`return`と書かなくても、**一番最後に評価された行の値が、自動的に返り値になる**。

**もし`new_folder`の行が無かったら何が起きるか**

最後から2番目の行`children.each { ... }`は、`.each`メソッド。**`.each`は中身を1個ずつ処理した後、「元のコレクション自体」をそのまま返す**、という仕様がある。もし`new_folder`と書かずにここで終わっていたら、`duplicate_into`は「今複製した新しいフォルダ」ではなく、「**複製元が持ってた、子フォルダの一覧(`children`)**」を返してしまう。これは欲しい情報とは全く違う。

なので最後に`new_folder`とだけ書いて、「この関数の返り値は、`children.each`の結果ではなく、今複製して保存した新しいフォルダ自身にする」と明示的に上書きしている。

**なぜこれが必要か(呼び出し①に立ち返って確認)**

`deep_duplicate`はこうなっている。

```ruby
def deep_duplicate
  ActiveRecord::Base.transaction do
    duplicate_into(parent_id)
  end
end
```

`transaction`ブロックの返り値も、同じルールで「中の最後の行の値」になる。呼び出し①(`写真.duplicate_into(nil)`)が`new_folder`(=id100の「写真_copy(1)」)を返すおかげで、`deep_duplicate`自身も「複製した、一番大元の新しいフォルダ」を呼び出し元に返せるようになる。これは次の手順(コントローラーで、複製結果をJSONとして返す)で必要になる。

(呼び出し②の`旅行.duplicate_into(100)`の返り値自体は、`children.each`のブロックの中で使い捨てられていて、誰も受け取っていない。返り値が実際に使われるのは、一番外側の呼び出し①の結果だけ。)

---

## まとめ

- `target_parent_id`は、`duplicate_into`が呼ばれるたびに変わる、**その呼び出し限定の値**
- 「今、誰を複製してるか(`self`)」によって、`target_parent_id`が指す相手(=複製先の親)も変わる
- `next_copy_name`は親フォルダを探しに行くのではなく、`parent_id`を検索条件にして**兄弟**を探しに行く
