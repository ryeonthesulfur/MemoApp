# クラスメソッドを使う状況の解説  260914

「`def self.next_copy_name`の`self.`って何のためについてるの?」という疑問から始まり、「クラスメソッドはどういう状況で使うものか」という軸で整理した内容のまとめ。

---

## 0. お題にするコード

```ruby
class Memo < ApplicationRecord
  def self.next_copy_name(base_title, folder_id)
    base = base_title.to_s.sub(/_copy\(\d+\)\z/, "")
    max_n = where(folder_id: folder_id)
              .where("title LIKE ?", "#{base}_copy(%")
              .filter_map { |m| m.title[/_copy\((\d+)\)\z/, 1]&.to_i }
              .max || 0
    "#{base}_copy(#{max_n + 1})"
  end
end
```

呼び出し側:

```ruby
Memo.next_copy_name(@memo.title, @memo.folder_id)
```

---

## 1. `self.`の有無で何が変わるか

Rubyのクラスの中で、`def`の前に`self.`が付いてるかどうかで、そのメソッドの種類が変わる。

| 書き方 | 種類 | 呼び出し方 |
|---|---|---|
| `def next_copy_name` | インスタンスメソッド | `memo.next_copy_name(...)`(個々のメモに対して) |
| `def self.next_copy_name` | クラスメソッド | `Memo.next_copy_name(...)`(Memoクラス自体に対して) |

`next_copy_name`は`Memo.next_copy_name(...)`という形で呼ばれているので、`self.`付きの**クラスメソッド**として定義する必要がある。

---

## 2. なぜ`next_copy_name`はクラスメソッドなのか

`next_copy_name`がやってることは、「特定の1個のメモの中身について何か聞く」処理ではなく、「**Memoテーブル全体の中から、条件に合うものを検索する**」処理。

```ruby
max_n = where(folder_id: folder_id)   # ← ここ
```

`self.`が付いたクラスメソッドの中では、この`where`は暗黙的に`Memo.where(...)`(=Memoテーブル全体を検索する)という意味になる。これは「今ここにある、特定の1個のメモ」に対する操作ではなく、**Memoという集まり全体**に対する操作。

---

## 3. `Memo.new(...)`も同じ理由でクラスメソッド

`create`アクションにある、以下のコードも考えてみる。

```ruby
memo = Memo.new(memo_params)
```

`new`も`Memo.new(...)`という、クラス自体に対する呼び方。これも`next_copy_name`と同じ理由でクラスメソッドになっている。

**共通してるのは「操作対象となる、特定の既存インスタンスがまだ無い」という点**

- `next_copy_name`: これから検索する対象は「複数のメモたち」であって、「今すでに手元にある、特定の1個のメモ」ではない
- `new`: これから作ろうとしてるのは「まだ存在しない、新しい1個」であって、「今すでに手元にある、特定の1個のメモ」ではない

(補足: `next_copy_name`は「既存のデータを検索する」、`new`は「まだ存在しない新しいオブジェクトを作る」という点で、やってる**処理の中身**は全然違う。共通してるのは「操作対象が、特定の既存インスタンス単体ではない」という点だけ。`new`自体はDBに一切アクセスしておらず、メモリ上でオブジェクトを組み立てているだけ。実際にDBへ保存されるのは、この後`.save`が呼ばれた瞬間。)

---

## 4. インスタンスメソッドとの対比

一方、以下のようなメソッドはインスタンスメソッド。

```ruby
memo.save
memo.title = "新しいタイトル"
```

これらは、**既に(メモリ上に)存在する、特定の1個のオブジェクト**に対して行う操作。そのオブジェクトが手元に無いと、そもそも呼び出しようがない。

---

## 5. 使い分けの軸(まとめ)

**「この処理は、既に存在する特定のインスタンスに対して行うものか?」** を基準に考える。

| 判断 | 種類 | 例 |
|---|---|---|
| 特定の既存インスタンスに対する操作 | インスタンスメソッド | `memo.save`、`memo.title = ...` |
| 特定の既存インスタンスに紐づかない操作(コレクション全体の検索、新規作成など) | クラスメソッド | `Memo.where(...)`、`Memo.new(...)`、`Memo.next_copy_name(...)` |

「対象となる特定のインスタンスが、既に手元にあるかどうか」が、インスタンスメソッドとクラスメソッドを使い分ける基準になる。
