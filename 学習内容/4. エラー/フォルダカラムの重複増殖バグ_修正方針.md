# フォルダカラムの重複増殖バグ、修正方針  260809

無限カラム表示機能([フォルダの無限カラム表示_設計方針.md](./フォルダの無限カラム表示_設計方針.md))を実際に使ってみたところ見つかった不具合と、直し方の方針のまとめです。

---

## 今、実際に起きている不具合(3パターン)

### ① メインパネルのフォルダを2回以上クリックすると、同じ内容のカラムが右にどんどん増える

```
[メインパネル] フォルダAをクリック
→ [メインパネル][カラムA]

[メインパネル] もう一度フォルダAをクリック
→ [メインパネル][カラムA][カラムA]   ← 同じものが2個並ぶ(バグ)
```

### ② 子フォルダでも同じことが起きる

カラムの中の子フォルダを2回クリックすると、同様に同じ子フォルダのカラムが重複して増える。

### ③ 深い階層を開いた後、別の枝(別のフォルダ)を選ぶと、古い階層が残ったまま右にどんどん追加される

```
[メインパネル] フォルダAをクリック → [メインパネル][カラムA]
[カラムA] 子フォルダBをクリック    → [メインパネル][カラムA][カラムB]

ここで [メインパネル] の別のフォルダCをクリックすると、
本来は [メインパネル][カラムC] になってほしいのに、実際は…

→ [メインパネル][カラムA][カラムB][カラムC]
   （AとBが残ったまま、Cが一番右に追加されてしまう。
     まるでBの中にCがある、という誤った階層に見える）
```

---

## 原因

`createFolderColumn(folderId, afterColumn)`という関数([folder_columns.js:20](../../app/javascript/folder_columns.js#L20))は、呼び出す側では「どのカラムの次に追加するか」を`afterColumn`として渡している。

```javascript
// メインパネルから呼ぶ時
createFolderColumn(icon.dataset.folderId, null);

// カラムの中の子フォルダから呼ぶ時
createFolderColumn(childIcon.dataset.folderId, column);
```

ところが、関数の中身は`afterColumn`を**一度も使っていない**。常にこの1行だけで新しいカラムを追加している。

```javascript
folder_columns_container.appendChild(column);
// ↑ afterColumn が null でも column でも、常に「一番右」に追加するだけ
```

つまり、今の実装には「クリックした場所より右にある、古いカラムを消す」という処理が一切存在しない。だから、何回クリックしても、どこをクリックしても、常に「右に追加され続ける」だけになっている。

---

## 直すべきルール

Finderの動きと同じ考え方にする。**あるカラム(またはメインパネル)でフォルダを選ぶと、その右側にあった古いカラムは全部無効になる**、というルール。

| クリックした場所 | すべきこと |
|---|---|
| メインパネル(`afterColumn = null`) | 今開いている**全カラムを削除**してから、新しいカラムを1つだけ追加する |
| あるカラムの中の子フォルダ(`afterColumn = そのカラム`) | `afterColumn`より**右にある全カラムを削除**してから、新しいカラムをその直後に追加する |

これを実装すると、①②の「重複」バグも同時に直る。理由: 同じフォルダをもう一度クリックした時も、まず「右側(＝今回は自分自身を含むそれ以降)を全部消す」→「新しく1個だけ追加する」という流れになるので、結果的に重複せず1個だけになる。

    } else {

    }
