# `main_title`の`show`クラスが、名前と逆の意味だった問題、修正レポート  260926

## 1. 何が問題だったか

大きい「MIND PALACE」の文字(`.main_title`)にだけ、`show`というクラス名が**「表示する」ではなく「消す」**という意味で使われていた。

コードを読む人は、`show`と書いてあれば「表示される」と読む。実際の動きは逆だったので、読み間違いが起きた。

---

## 2. 同じ`show`でも、要素によって効き方が違っていた

| 要素 | 何の文字か | 何も付いてない時 | `show`が付いた時 |
|---|---|---|---|
| `#header_title` | ヘッダーの「記憶」 | 見えない(`opacity: 0`) | **見える**(`opacity: 1`) |
| `.main_title` | 大きい「MIND PALACE」 | 見えている(`opacity: 1`) | **消える**(`opacity: 0`、`visibility: hidden`) |

該当のCSS(修正前、`top.css`):

```css
.main_title.show {
    opacity: 0;              /* 透明度を0%にしてフェードアウト */
    visibility: hidden;      /* クリックできないよう非表示にする */
}
```

`show`という名前なのに、中身は「消す」処理になっていた。

---

## 3. 実際に起きた混乱

`top.js`の「憶」をクリックした時の処理は、こう書かれている。

```javascript
header_title.classList.add('show');   // 「記憶」が出る
main_title.classList.add('show');     // MIND PALACEが消える(名前は show なのに)
```

上の2行は同じ書き方(`add('show')`)なのに、片方は「出す」、片方は「消す」になる。

この状態でコードを読むと、「憶」を押して`main_title`が出てくるように見える。実際は消える。この読み違いに加えて、コメントを書く側(Claude)も、CSSを確認せずに「`show`=表示」と思い込んで、間違った説明のコメントを書いた。そのため、コメントを直すたびに説明が食い違い、余計に分かりにくくなった。

---

## 4. 直したこと

`main_title`だけ、クラス名を実際の動き(消す)に合わせて`hide`に変えた。

| ファイル | 変更内容 |
|---|---|
| `top.css` | `.main_title.show` → `.main_title.hide` |
| `top.js`(2箇所) | `main_title.classList.add('show')` → `add('hide')`、`remove('show')` → `remove('hide')` |
| `sound.js`(2箇所) | 同上 |

**注意**: 最初は「`top.css`と`top.js`の3行だけ」と考えていたが、作りかけの`sound.js`にも同じ使い方があった。名前を変える時は、使っている箇所を全部変えないと、変え忘れた場所だけ動かなくなる。変更前に`grep`で`main_title`の使用箇所を全部探して、`sound.js`が見つかった。

---

## 5. 今回の教訓

- **クラス名から動きを推測しない。** 名前が`show`でも、実際に何が起きるかはCSSを見ないと分からない。
- **コードの説明(コメント)を書く前に、実際の動きを確認する。** 今回は、確認せずに書いたコメントが間違っていて、混乱を増やした。
- **名前と実際の動きがズレていたら、コメントで補うより、名前を直す。** コメントを足すより、名前を実態に合わせる方が、読む人に伝わる。
- **名前を変える前に、`grep`で使っている場所を全部探す。**
