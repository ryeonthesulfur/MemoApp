# 「head :no_content」の意味  260901

削除機能(`destroy`アクション)で出てきた`head :no_content`について、今まで使ってきた`render json: ...`との違いをまとめます。

---

## 今までの`render`との対比

| 書き方 | レスポンスの中身(ボディ) | 使う場面 |
|---|---|---|
| `render json: @memo` | JSONデータが入る | 保存・取得・更新した中身をJSに返したい時(`create`・`show`・`update`) |
| `head :no_content` | **空っぽ**(何も入らない) | 削除した時(`destroy`) |

`head`は「ヘッダーだけ返す(中身は返さない)」という意味の書き方です。`render`が「中身(ボディ)込みで返す」のに対して、`head`は中身を空にして、ステータスコードだけを返します。

---

## なぜ削除の時は中身が空でいいのか

`create`・`show`・`update`の場合は、「保存(または取得)された中身」をJSに教えてあげる必要があります。だから`render json: @memo`のように、実際のデータを返してます。

でも`destroy`の場合、処理が終わった時点でそのレコードはもうDBに存在しません。返すべき「中身」自体が無いので、空っぽのレスポンスで十分、というのがRailsの定番の考え方です。

---

## `:no_content`が指してるもの

`:no_content`は、HTTPステータスコード`204 No Content`のRailsでの書き方(シンボル)です。

- `200` → 成功(中身あり)
- `201` (`status: :created`) → 成功、新しく作られた(`create`アクションで使ってる)
- `204` (`:no_content`) → 成功、でも返す中身は無い(`destroy`アクションで使う)

つまり「削除、ちゃんと成功しましたよ。でも見せるものは何もありません」という意味のステータスコードです。

---

## JS側ではどう使うか

JS側(`fetch`)では、`response.json()`で中身を取り出す必要はありません(中身が無いので取り出しようがない)。代わりに、`response.ok`(成功したかどうかの真偽値)だけを見て、成功していたら画面からアイコンを消す、という使い方になります。

```javascript
const response = await fetch(`/memos/${memoId}`, { method: 'DELETE', ... });
if (response.ok) {
  icon.remove(); // 削除に成功したら、画面からも消す
}
```
