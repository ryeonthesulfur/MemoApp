# 【バグ解説】保存した直後の新規メモだけ、クリックしても開けない

## 症状

- 新しくメモを保存した直後、一覧に出てきたその**新規メモのアイコン**をクリックしても、中身を見るパネルが開かない
- **他の(前から存在する)メモ**のアイコンは、クリックすると正しく開ける
- **ページをリロードすると**、その新規メモも普通に開けるようになる

「保存した直後だけ」「リロードすれば直る」という2つの手がかりから、原因を追っていきます。

---

## 手がかり1: 「リロードすれば直る」ということは

リロードで直るということは、**データベースには正しく保存されている**ということです(壊れたデータが保存されてるわけではない)。問題は、**保存した直後、リロードせずにその場に表示されてるアイコン(JSが作ったアイコン)側**にあります。

## 手がかり2: アイコンの「生まれ方」が2種類ある

このアプリのメモアイコンは、実は2つの別々のコードから作られています。

| 作られ方 | どこで | いつ |
|---|---|---|
| ① サーバーが作る(ERB) | `index.html.erb`の`<% @memos.each do |memo| %>` | ページを開いた時(リロード時) |
| ② JSがその場で作る | `memo_saving.js`の`document.createElement('div')` | 保存ボタンを押した直後 |

**この2つが、全く同じ見た目・同じHTML構造になっていないと、後の処理で不整合が起きます。**

---

## 実際に見比べてみる

**① サーバーが作るアイコン(`index.html.erb`)**

```erb
<div class="folder-icon" data-memo-id="<%= memo.id %>">
  <span class="material-symbols-outlined color-blue">description</span>
  <span class="folder-name"><%= memo.title.presence || "名称未設定メモ" %></span>
</div>
```

`data-memo-id="3"`のように、**そのメモのIDが属性として付いています。**

**② JSがその場で作るアイコン(修正前の`memo_saving.js`)**

```javascript
const new_memo = document.createElement('div');
new_memo.classList.add('folder-icon');
new_memo.innerHTML = `
  <span class="material-symbols-outlined color-blue">description</span>
  <span class="folder-name">${savedMemo.title || '無題'}</span>
`;
window.icon_container.appendChild(new_memo);
```

クラス名(`folder-icon`)や見た目(アイコン・名前)は同じように作られていますが、**`data-memo-id`をセットする行がどこにもありません。**

---

## なぜ`data-memo-id`が無いと、クリックしても反応しないのか

`show_panel.js`のクリック処理を見ると、こうなっています。

```javascript
icon_container.addEventListener('click', function (e) {
  if (e.target.classList.contains('folder-name')) {
    return;
  }

  const icon = e.target.closest('.folder-icon');
  if (!icon || !icon.dataset.memoId) return; // ← ここ
  //...
});
```

`if (!icon.dataset.memoId) return;`は、「`data-memo-id`が付いてないアイコンは、メモじゃない(静的なフォルダなど)とみなして、何もせず処理を終える」という条件です。

**JSがその場で作ったアイコンには`data-memo-id`が無いので、この条件に引っかかって「メモじゃない」と判定され、クリックしても無視されていました。** サーバーが作ったアイコンには最初から`data-memo-id`が付いているので、この条件をすり抜けて正しく動いていた、という違いです。

```
サーバーが作ったアイコン → data-memo-id あり → クリックで正しく開く
JSがその場で作ったアイコン → data-memo-id なし → 「メモじゃない」と判定され、無視される
      │
      ▼
リロードすると、サーバーが作り直す(data-memo-id付き) → 直る
```

---

## 修正内容

`memo_saving.js`で新しいアイコンを作ってる部分に、`data-memo-id`を追加します。

```javascript
const new_memo = document.createElement('div');
new_memo.classList.add('folder-icon');
new_memo.dataset.memoId = savedMemo.id; // ← この1行を追加
new_memo.innerHTML = `
  <span class="material-symbols-outlined color-blue">description</span>
  <span class="folder-name">${savedMemo.title || '無題'}</span>
`;
window.icon_container.appendChild(new_memo);
```

`要素.dataset.memoId = 値`と書くと、HTMLの`data-memo-id="値"`という属性として自動的に反映されます。`savedMemo.id`は、保存に成功した時にRailsから返ってきたJSON(`render json: memo, status: :created`)に入っている、そのメモの実際のIDです。

---

## この失敗から得られる教訓

**同じ見た目のものを、2つの別々のコード(サーバー側のERBとJS側のDOM操作)で作る場合、見た目だけでなく「他のコードが依存してる属性」まで、両方に同じように用意する必要があります。**

今回、`class="folder-icon"`(見た目・CSSのため)は両方に書かれていましたが、`data-memo-id`(クリック判定のため)は片方(ERB側)にしか書かれていませんでした。「見た目が同じだから同じもの」とは限らず、**それぞれの属性が何のために使われているか**を意識して、両方のコードを揃える必要がある、というのが今回の教訓です。
