# フォルダの無限カラム表示、設計方針  260808

フォルダをクリックするたびに、その中身を表すカラム(パネル)が右にどんどん増えていく機能の、全体設計まとめです。

---

## なぜ今の実装(1個の固定パネル)では足りないのか

今までの`#folder_show_panel`は、HTMLに**1つだけ**あらかじめ用意した箱でした。これだと、フォルダの中のフォルダをさらに開く、というような「何階層でも深く行ける」動きには対応できません(箱が1個しかないので、上書きするしかなく、今どこにいるか(パス)が分からなくなる)。

なので、**カラムそのものをJSでその場で作る**方式に変える必要があります。

---

## 設計方針、5つの柱

### 1. カラムを作る「雛形関数」を1つだけ用意する

```javascript
function createFolderColumn(folderId) {
  // このフォルダの中身を表示する、1個のカラムをJSで丸ごと組み立てて追加する
  // 戻り値: 作ったカラムのDOM要素
}
```

メインパネルからでも、カラムの中からでも、**同じ関数を呼ぶだけ**。呼ばれた数だけカラムが増える。

### 2. カラムを並べる「入れ物」を1つ用意する(flexboxで自動配置)

```css
#folder_columns_container {
  position: absolute;
  left: 34%;
  top: 14%;
  height: 80%;
  display: flex;
  gap: 16px;
  overflow-x: auto;
}
```

`display: flex`にしておけば、カラムの追加・削除に応じて、位置を自分で計算しなくても自動で横に並ぶ。

### 3. 「今開いてるフォルダのID」は、カラム自身(`dataset`)に持たせる

以前は`currentFolderId`という**1個だけの変数**で管理していたが、カラムが複数になるとこれでは足りない。カラムのDOM要素自体に持たせる。

```javascript
column.dataset.folderId = folderId;
```

これで、カラムがいくつあっても、それぞれ「自分がどのフォルダの中身か」を自分で覚えている。

### 4. カラムの中の「フォルダ」をクリックしたら、また同じ関数を呼ぶ(再帰)

```
カラムの中のフォルダアイコンがクリックされたら
  → createFolderColumn(クリックされたフォルダのid) を呼ぶ
  → 新しいカラムが、入れ物の一番右に追加される
```

1階層目でも5階層目でも同じ処理なので、無限に深くできる。

### 5. カラムを閉じたら、その右側(＝もっと深い階層)のカラムも一緒に削除する

```
[メインパネル] [カラム1] [カラム2] [カラム3]
                  ↑ここを閉じると
[メインパネル]
(カラム1・2・3、まとめて消える。カラム1を閉じる=その中身を見るのをやめる、ということなので、その内側の階層も一緒に閉じるのが自然)
```

```
                  folderId=A   folderId=B   folderId=C
              (それぞれ自分のfolderIdをdatasetに持つ)
```

## これまでの実装からの変更点

| 項目 | 今まで | これから |
|---|---|---|
| カラムの数 | 1個(HTMLに固定) | 何個でも(JSで動的に作る) |
| 「今どのフォルダを開いてるか」の管理 | `let currentFolderId`(変数1個) | 各カラムの`dataset.folderId`(カラムごと) |
| カラムの配置 | CSSで`left: 34%`と固定 | `display: flex`の入れ物に入れて自動配置 |
| カラムを閉じる処理 | そのカラムだけ`show`を外す | そのカラムと、右側の全カラムを削除 |

## 使い回せる部分(書き直し不要)

- `Folder`モデル、マイグレーション、`FoldersController`(`create`・`show`)
- `fetch`で保存する処理、CSRFトークンの取得
- `parent_id`で親子を紐づける考え方
- 入力欄(`<input>`)を`<span>`に差し替える処理
