# 古いカラムを片付ける処理、解説  260906

`folder_columns.js`の`createFolderColumn`関数、一番最初の部分(下記)が何をしてるか、図解でまとめます。

```javascript
async function createFolderColumn(folderId, afterColumn) {

    if (afterColumn === null) {
        folder_columns_container.innerHTML = '';
    } else {
        while(afterColumn.nextElementSibling) {
            afterColumn.nextElementSibling.remove();
        }
    }

    const response = await fetch(`/folders/${folderId}`);
    const folder = await response.json();
```

---

## 1. この関数がやりたいこと(全体像)

クリックされたフォルダの中身を新しいカラムとして開く前に、「もう見なくていい、古いカラム」を片付けることです。

なぜ片付けが必要かというと、フォルダのカラムを1つ作るたびに、この関数が何度も呼ばれるからです。同じ関数を使い回してるので、呼ばれるたびに「今回はどこを片付ければいいか」を毎回判断する必要があります。

---

## 2. この関数が呼ばれる、2つの場面

画面の操作としては、フォルダをクリックすると右にパネル(カラム)が開いていきます。この「クリックしてカラムを開く」という動作には、実は2つの別の場面があります。

**場面A: メインパネルのフォルダをクリックした時**

一番左にある、常に表示されてるメインパネル。ここのフォルダアイコンをクリックした場合です。この時は「一番根本から選び直した」ことになるので、今まで右に開いていたカラムは全部、もう用済みです。

**場面B: 開いてるカラムの中の、子フォルダをクリックした時**

すでに右に何個かカラムが開いている状態で、その中の1つのカラムの中にある子フォルダをクリックした場合です。この時は「そのカラムより右側」だけが用済みで、クリックしたカラム自身とそれより左は、まだ関係があります。

この関数(`createFolderColumn`)は、場面Aと場面Bのどちらで呼ばれても同じ1つの関数として動きます。なので関数の中で「今回はA・Bどっちの場面か」を判断する必要があり、それを教えてくれるのが`afterColumn`という引数です。

- 場面Aの時 → `afterColumn`には`null`が渡ってくる
- 場面Bの時 → `afterColumn`には、クリック元のカラム(DOM要素)が渡ってくる

---

## 3. パターンA: `afterColumn === null`(メインパネルから)

```javascript
folder_columns_container.innerHTML = '';
```

メインパネルで別のフォルダを選び直した、ということは「今まで開いてたカラムは全部、もう関係ない」という意味です。なので`folder_columns_container`(全カラムの入れ物)の中身を、まるごと空にします。

```
Before: [メインパネル] [カラムA] [カラムB] [カラムC]
                          ↓ メインパネルの別フォルダをクリック
After:  [メインパネル]  (何も無い)
                          ↓ この後、クリックされたフォルダの中身が新しいカラムとして開かれる
Final:  [メインパネル] [新カラム(選んだフォルダの中身)]
```

---

## 4. パターンB: `afterColumn`がカラム(カラムの中の子フォルダから)

```javascript
while(afterColumn.nextElementSibling) {
    afterColumn.nextElementSibling.remove();
}
```

こちらは「クリック元のカラムより右にあるものだけ」を消したいので、全部を空にする(パターンAのやり方)は使えません。代わりに、1個ずつ右隣を消していく、地道な繰り返し処理を使います。

### 具体例で追ってみる

今、画面がこうなってるとします。

```
[メインパネル] [カラムA] [カラムB] [カラムC]
```

カラムAの中の、別の子フォルダをクリックしたとします(`afterColumn` = カラムA)。

| 周目 | 「Aの次の要素は?」 | やること | 結果 |
|---|---|---|---|
| 1周目 | カラムBがある | Bを消す | `[メインパネル] [カラムA] [カラムC]` |
| 2周目 | (Bが消えたのでCが繰り上がる)カラムCがある | Cを消す | `[メインパネル] [カラムA]` |
| 3周目 | もう何も無い | ループ終了 | `[メインパネル] [カラムA]` |

`nextElementSibling`は「自分のすぐ右にある要素」を指すDOMのプロパティです。1個消すと、その次にあった要素が自動的に「新しい隣」として繰り上がってくるので、`while`で「隣がまだある間、消し続ける」という書き方が成立します。

---

## 5. 最後の2行(片付け終わった後)

```javascript
const response = await fetch(`/folders/${folderId}`);
const folder = await response.json();
```

片付けが終わった後、今度は「クリックされたフォルダの中身(名前・子フォルダ一覧・メモ一覧)」を、Railsに取りに行きます。この2行はもう片付けとは無関係で、次のステップ(カラムの見た目を組み立てる)のための準備です。

- `fetch(...)` → サーバーに「このidのフォルダの情報をちょうだい」とリクエストを送る
- `response.json()` → 返ってきたJSON文字列を、JSで扱えるオブジェクトの形に変換する

---

## まとめ

| afterColumn | 意味 | やること |
|---|---|---|
| `null` | メインパネルから選び直した | 全カラムを消す(`innerHTML = ''`) |
| カラム自身 | そのカラムの中の子フォルダを選んだ | そのカラムより右だけを、1個ずつ消す(`while`ループ) |

どちらのパターンでも、片付けが終わった後は同じように、クリックされたフォルダの情報をサーバーから取りに行く処理に合流します。
