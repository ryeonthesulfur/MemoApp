# 【総括】fetchの使い方、完全解説

## 結論を先に1行で

**`fetch`は「1回のリクエストにつき1回」書きます。同じ`fetch`を複数の場所で使い回すことはできません。** ただし「URLの形(パターン)」は使い回せます。この「形は共有できるが、呼び出し自体は共有できない」がこのドキュメントの核心です。

---

## このアプリに出てくる2つの`fetch`

`show_panel.js`には、`fetch`が2回出てきます。

| | ①表示用(show) | ②保存用(update) |
|---|---|---|
| いつ実行される | メモのアイコンをクリックした瞬間 | 「保存」ボタンを押した瞬間 |
| HTTPメソッド | `GET`(省略時のデフォルト) | `PATCH` |
| Railsのどのアクションが動くか | `MemosController#show` | `MemosController#update` |
| やってること | メモの中身を「もらう」 | 編集後の中身を「送って上書きする」 |

```javascript
// ①表示用
fetch(`/memos/${memoId}`)
  .then(response => response.json())
  .then(memo => { /* 表示する処理 */ });

// ②保存用
fetch(`/memos/${currentMemoId}`, {
  method: 'PATCH',
  headers: { 'Content-Type': 'application/json', 'X-CSRF-Token': csrfToken },
  body: JSON.stringify({ memo: { title: ..., content: ... } }),
})
  .then(response => response.json())
  .then(updatedMemo => { /* 保存完了後の処理 */ });
```

見た目は似ていますが、**別の関数(別のイベントリスナー)の中に、別々に書かれています。**

---

## なぜ2つとも別々に書く必要があるのか

**この2つは「起きるタイミング」が全く違うから**です。

```
[ページを開く]
      │
      │ ... (しばらく何も起きない) ...
      │
      ▼
[ユーザーがメモのアイコンをクリック] ← ここで①のfetchが実行される
      │
      │ ... (ユーザーがタイトルや本文を書き換える。数秒〜数分かかることも) ...
      │
      ▼
[ユーザーが「保存」ボタンをクリック] ← ここで②のfetchが実行される
```

①と②の間には、**ユーザーが実際に文字を書き換えるという、予測できない時間差**があります。①を実行してる時点では、ユーザーがいつ保存ボタンを押すか(あるいは押さずに閉じるか)、JS側には分かりません。なので、①のコードの中で②の処理まで一緒にやることはできません。**別々の「クリック」という別々のきっかけに反応する必要があるので、コードとしても別の場所に、別々に書く**しかないのです。

---

## 「URLの形は共有できる」の正確な意味

以前、「同じ`/memos/${id}`という形は使い回せる」という話をしました。これは**「文字列としてのパターンを、2箇所で同じルールで組み立てている」**という意味であって、**「1つの`fetch`の呼び出し自体を2箇所で使い回す」という意味ではありません。**

```
① fetch(`/memos/${memoId}`)          ← memoId を使って組み立てた、①専用のURL文字列
② fetch(`/memos/${currentMemoId}`)   ← currentMemoId を使って組み立てた、②専用のURL文字列
```

見た目(パターン)は同じでも、**実行される瞬間も、実際に埋め込まれる値も、リクエストの中身(GETかPATCHか)も別**です。なので「共有」ではなく、「同じ書き方のルールを、別々の場所で2回使っている」というのが正確な理解です。

```
              「/memos/:id」というURLのパターン
              (routes.rb の resources :memos が決めたルール)
                     │
        ┌────────────┴────────────┐
        │                         │
   ①表示用のfetchが            ②保存用のfetchが
   このパターンに沿って          このパターンに沿って
   GETリクエストを作る           PATCHリクエストを作る
   (アイコンクリック時)          (保存ボタンクリック時)
```

---

## まとめ

- `fetch`は、1つの`fetch(...)`の呼び出しにつき、1回のHTTPリクエストを表す
- 「表示」と「保存」は、起きるタイミングも目的も違う、別々の出来事
- 別々の出来事には、別々の`fetch`が必要(使い回しはできない)
- 使い回せるのは「URLの組み立て方のパターン」だけで、「呼び出しそのもの」は共有できない
